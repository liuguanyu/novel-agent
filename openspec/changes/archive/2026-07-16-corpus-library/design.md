## Context

素材库承载“弱参考”的创作原材料，与事实库（强约束）正交。它把导入的外部素材自动提炼为可语义检索的
灵感/高光/桥段/叙事逻辑/风格样本，供写作时按需借鉴，且可跨项目复用。本 change 只定义数据模型、
提炼与检索契约，不实现 agent 编排。

## Goals / Non-Goals

**Goals:**
- 定义素材条目模型与类型（高光/风格/桥段/叙事逻辑/灵感碎片，可扩展）。
- 定义导入意图分流：同一素材可作为本作正文、参考素材或两者。
- 自动提炼候选条目，用户可改/确认/打标签/删除。
- 提供语义检索（向量）与按标签/来源过滤。
- 支持跨项目全局素材库与项目选择性挂载。

**Non-Goals:**
- 不构成任何约束、不触发一致性检查（那是 story-bible 的职责）。
- 不实现写作/召唤 agent 的编排（agent-orchestration）。
- 不实现事实抽取（story-bible）。
- 不编写实现代码。

## Decisions

### D1. 素材与事实正交，导入时按意图分流
- 事实库 = 强约束、结构化、本作权威事实；素材库 = 弱参考、语义检索、可跨项目。
- 同一份导入素材，用户 MUST 能选择其归宿：作为本作正文（→ story-workspace/story-bible）、
  作为参考素材（→ 素材库）、或两者兼有。
- 素材条目 MUST NOT 进入一致性检查，MUST NOT 产生 bug；它只是可取可不取的灵感输入。

### D2. 素材条目模型
- 每条目含：`type`（highlight 高光片段 / style-sample 风格样本 / plot-device 情节桥段 /
  narrative-logic 叙事逻辑 / spark 灵感碎片，可扩展）、`content`、`tags`、`source`（来源，可空）。
- 条目为语义检索单元，需可被 embedding。

### D3. 自动提炼为主、人工可改
- 从导入素材自动提炼候选条目（如识别高光对白、可复用桥段结构）。
- 用户 MUST 能对候选条目进行修改、确认、打标签、删除；提炼结果不锁定。
- 提炼涉及模型调用，其 prompt/agent 由 agent-orchestration 装配；本 change 定义提炼输入/输出契约。

### D4. 语义检索 + 过滤
- 支持按语义相似度检索（向量检索），用于“写到某场景时找类似氛围/桥段”。
- 支持按标签、来源、类型过滤，及与语义检索组合。
- embedding 计算属 CPU 密集，MUST 在 utilityProcess 执行；向量库读写作为 I/O 归 Main。

### D5. 作用域：跨项目全局库 + 项目挂载
- 素材库支持跨项目的全局仓库，作者的风格/桥段可沉淀复用到未来作品。
- 项目 MUST 能选择性挂载全局库或使用项目私有素材；检索时可限定作用域（单篇/项目/全局）。

## Risks / Trade-offs

- **风险：自动提炼噪声。** 缓解：人工可改/删/打标签，提炼仅产候选。
- **风险：跨项目素材与当前作品风格不符被误用。** 缓解：弱参考语义 + 作用域限定 + 检索按需，不强制注入。
- **合规：素材可能含非原创内容。** 定位为个人本地参考用途，不外发、不用于训练；在 spec 中显式声明边界。
- **权衡：向量库选型（Chroma/LanceDB 等）留待实现。** 本 change 只定义检索契约，不锁定具体库。
