## Why

当前专家工作台只能解释一次 `runId` 内真实经过了哪些 LangGraph 节点，无法说明作者正在执行哪一类长期业务流程、完整阶段、当前阶段、下一步及人工裁决后的去向。结果是人物设计等多轮讨论会被切成互不关联的运行，新书创作与老书审校修订也都缺少可执行、可追踪的闭环。

本 change 单独建立“业务工作流引导”能力：在保留真实节点轨迹的同时，以跨多次运行的长期工作流实例承载新书创作和老书修订路径，并把审校问题、局部修改、checkpoint 与复检串成可关闭的业务闭环。

## What Changes

- 新增长期 `WorkflowInstance`：以独立 `workflowId` 聚合多个 `runId`，持久化工作流类型、阶段、状态、当前阶段、下一步、阶段产物和运行归属。
- 新增两套内置模板：
  - 新书创作：立意定位 → 世界观 → 人物设计 → 全书大纲 → 章节规划 → 分场大纲 → 正文写作 → 事实抽取 → 自动审校 → 人工修改/验收 → 章节定稿/下一章 → 全书总检。
  - 老书审校修订：导入 → 全书事实回填 → 全书总检 → 问题分级/选择 → 原文定位 → 局部改写方案 → 逐 hunk 裁决 → 落盘/checkpoint → 针对性复检 → 问题关闭 → 最终全书复检。
- 专家工作台升级为双层视图：上层展示业务阶段计划、当前阶段、阻塞原因与下一步；下层继续展示当前阶段内真实 LangGraph 节点轨迹。
- 明确阶段推进规则：自动质量门可自动推进；策划产物、冲突裁决、逐 hunk 写入和章节定稿等关键节点必须由作者确认；失败、暂停、跳过均有可测试语义。
- 明确对话与 `@专家` 的归属：默认作为当前阶段内迭代并保留专家亲和性；显式开始/切换工作流才改变长期流程；无活动工作流的单次召唤继续兼容。
- 新增可版本化创作资产：立意、世界观、人物、全书大纲、章节规划和分场大纲不再只停留在对话/currentDraft；作者可在任意阶段澄清并经确认写入目标资产。
- 新增资产影响传播：人物/世界观约束同步到 Story Bible；资产新版本使依赖旧版本的规划、正文或审校结果标记 stale/needs-review/conflicting，但不静默重写作者内容。
- 新增审校问题生命周期 `open / fixing / verifying / resolved / dismissed`，将问题与正文锚点、局部 diff、checkpoint 和复检结果关联。
- 修正恢复路由：人工裁决后根据工作流阶段与中断来源决定恢复目标，不再把所有 `correct` / `modify` 固定导向 writer。
- 修正 `suggestedFix` 语义：它是修改建议而非可直接落盘的改写正文；作者或改写专家必须提供实际改写片段后才能计算 diff。
- 将全书总检的“一键修复占位”升级为受工作流约束的局部修复闭环，仍强制逐 hunk 接受/拒绝，禁止整章覆盖。
- 保留无长期工作流的现有按需召唤模式，不强迫所有专家调用进入模板。

## Capabilities

### New Capabilities

- `workflow-instance`: 长期工作流实例、阶段状态、跨 run 关联、持久化与恢复契约。
- `workflow-templates`: 新书创作与老书审校修订的阶段模板、质量门和推进规则。
- `workflow-issue-lifecycle`: 审校问题从发现、修复、复检到关闭的状态与关联模型。
- `creative-assets`: 立意、世界观、人物与各级大纲的持久化资产、任意阶段澄清、版本、Story Bible 映射及影响传播。

### Modified Capabilities

- `expert-workbench-graph`: 从单次运行轨迹扩展为“业务阶段计划 + 当前阶段真实节点轨迹”双层工作台。
- `orchestration-state`: 运行状态增加可选工作流/阶段上下文引用，但不把完整长期实例塞入 LangGraph 状态。
- `orchestration-graph`: 专家运行挂载到阶段，且中断恢复目标由阶段规则和来源决定。
- `interrupt-resume`: 中断 payload 与恢复命令关联 `workflowId` / `stageId`，恢复后按阶段 continuation 执行。
- `review-findings-ui`: 问题卡片展示生命周期、工作流归属和可用的修复/复检动作。
- `refactor-review-ui`: 修正建议与改写正文的语义，并把 hunk 应用结果关联问题与 checkpoint。
- `quality-dashboard`: 将全书问题纳入修复闭环，以针对性复检和最终全书复检确认关闭。
- `ipc-contract`: 新增强类型工作流/资产快照、命令和事件，并允许既有运行事件携带可选工作流与资产关联。
- `fact-model`: 扩展事实出处，使作者确认的人物/世界观资产可作为可审计来源，同时保持正文事实与大纲计划语义分离。

## Impact

- Core：新增工作流领域模型、模板目录、阶段状态机、问题生命周期与创作资产/影响模型；保持框架无关，不依赖 React/Electron/LangGraph。
- Main：新增工作流与创作资产应用服务和 SQLite 持久化；把现有编排、Story Bible、事实回填、总检、diff/hunk、checkpoint、影响分析与复检能力接入阶段推进。
- utilityProcess：继续承载全书事实回填、Map-Reduce 总检及其他 CPU 密集任务；不新增 Renderer 侧业务计算。
- Renderer：专家工作台呈现业务阶段与当前运行轨迹；问题卡片、改写审阅和质量仪表盘消费强类型快照/事件并上报意图。
- IPC：新增工作流查询/命令/事件 DTO；既有单次召唤和 `runId` 事件向后兼容。
- 数据：SQLite 新增工作流实例、阶段运行关联、创作资产版本/依赖、问题状态及 checkpoint 关联记录，需要可回滚迁移。
- 依赖：优先复用现有 LangGraph、SQLite、diff/hunk、checkpointer 与审校模型，不引入新的外部运行时依赖。
