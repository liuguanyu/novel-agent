## MODIFIED Requirements

### Requirement: 节点据运行状态实时染色

活图 MUST 据当前运行状态给节点着色，区分至少「空闲 / 运行中 / 完成 / 出错 / 待裁决」，并 MUST 对运行中的节点呈现活动指示（如脉冲）。染色数据 MUST 以可容纳多个节点同时具态的模型（节点 id → 活动态映射）承载，MUST NOT 写死为「只能点亮单一节点」的结构。染色数据源 MUST 为后端逐节点 `graph-node-activated` 控制事件（enter→运行中、exit→完成），一次多跳运行 MUST 按实际执行序列点亮所经节点，MUST NOT 依赖从对话 turns 推断的单跳投影。

#### Scenario: 多跳运行逐节点点亮
- **WHEN** 一次运行依序经过多个节点（如 supervisor→写手→审校→写手）
- **THEN** 活图 MUST 按事件到达顺序把各节点依次着为「运行中」并在其退出后转为「完成」
- **AND** 同一运行中已完成的节点 MUST 保持「完成」态呈现执行轨迹

#### Scenario: 待裁决态如实反映
- **WHEN** 某运行因一致性问题挂起等待作者裁决
- **THEN** 活图 MUST 把对应节点着为「待裁决」
- **AND** 作者裁决恢复或终止后 MUST 相应更新节点态

#### Scenario: 新一次运行重置轨迹
- **WHEN** 作者发起新一次召唤
- **THEN** 活图 MUST 清除上一轮运行的点亮轨迹并开始呈现本轮
- **AND** MUST NOT 把不同运行的轨迹混叠

#### Scenario: 染色模型容纳多节点
- **WHEN** 活动态数据模型承载运行信息
- **THEN** 其 MUST 为「节点 id → 活动态」的映射结构，可同时表达多个节点具态
- **AND** MUST NOT 以「当前唯一节点」的单值结构建模
